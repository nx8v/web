1. Alur kerja

nx8v init            # buat proyek (project.json + server.js + public/)
nx8v dev             # development: simpan HTML memuat ulang browser
nx8v start           # production: jalankan dari project.json
nx8v logs            # lihat nx8v.log
nx8v stop            # hentikan server
nx8v package         # folder distribusi siap kirim

2. Membuat proyek

cd D:\proyek-saya
nx8v init
  name        [proyek-saya]: aplikasi-toko
  description [An NX8V application]: Aplikasi toko sederhana
  port        [3000]: 4000

Hasil:

D:\proyek-saya\
├── project.json          # "dependencies": {}
├── server.js
├── modules\              # folder modul, masih kosong
└── public\
    ├── index.html
    ├── about.html
    └── assets\
        ├── css\style.css
        ├── js\app.js
        ├── fonts\
        └── images\32x32.png    # ikon merek NX8V

Folder assets tetap ada. CSS, JS, font, dan gambar tinggal di dalamnya. Di HTML pathnya ditulis pendek: /css/style.css, /js/app.js, dan /images/32x32.png. NX8V mencari berkas itu di public/ dulu, lalu di public/assets/, sebelum server.js dijalankan.

Halaman juga memasang <link rel="icon" href="/images/32x32.png">. Permintaan otomatis /favicon.ico memakai ikon yang sama bila proyek belum punya favicon.ico sendiri.

project.json:

{
  "name": "aplikasi-toko",
  "version": "1.0.0",
  "description": "Aplikasi toko sederhana",
  "main": "server.js",
  "nx8v": {
    "port": 4000,
    "desktop": {
      "icon": "./images/32x32.png",
      "state": "normal",
      "width": 800,
      "height": 560,
      "minWidth": 640,
      "minHeight": 400,
      "center": true,
      "maximizable": true,
      "resizable": true,
      "titlebar": true,
      "singleInstance": true,
      "productName": "aplikasi-toko",
      "shortcutName": "aplikasi-toko",
      "artifactName": "aplikasi-toko-Setup-${version}.exe"
    }
  },
  "dependencies": {},
  "repository": {
    "type": "git",
    "url": "https://github.com/nx8v/dependencies.git"
  },
  "scripts": {
    "start": "nx8v start",
    "dev": "nx8v dev",
    "stop": "nx8v stop"
  }
}

"icon": "./images/32x32.png" menunjuk berkas public/assets/images/32x32.png. Path panjang seperti ./public/assets/images/32x32.png tetap berlaku bila berkasnya ada di situ.

Port bisa dioverride tanpa mengubah file: nx8v start --port=5000, atau lewat environment NX8V_PORT / PORT (dibaca server.js).

│       └── index.js

│   ├── index.html

│       ├── fonts/
│       └── images/

NX8V melayani berkas di public/ sebelum server.js. Menambah halaman cukup dengan menaruh file di folder itu:

/public/index.html
/aboutpublic/about.html lalu public/about/index.html

Bila tidak ada berkas yang cocok, permintaan masuk ke server.js. Di situ cukup rute milik proyek, misalnya GET /api/hello. server.js hasil init tidak lagi memuat pemetaan folder.

Modul

Modul proyek ditaruh di modules/. Dua hal wajib:

  1. Nama di dependencies pada project.json.
  2. Berkas masuk index.js di folder yang ditunjuk nama itu.
"dependencies": {
  "cotoh": "1.0.0",
  "photos": "1.0.0"
}

Kuncinya nama modul. Nilainya versi. Folder selalu modules/ ditambah nama itu, jadi "cotoh": "1.0.0" berarti modules/cotoh/index.js.

Yang dibuatBentuk
Namakunci cotoh
Versi1.0.0
Foldermodules/cotoh
Berkas masukmodules/cotoh/index.js

Di HTML cukup nama itu:

<script type="module" src="cotoh"></script>

Browser meminta /cotoh. NX8V mengembalikan modules/cotoh/index.js. /cotoh/index.js adalah berkas yang sama. Nama yang tidak tertulis di dependencies tidak dilayani.

require('./modules/photos') di server.js juga membuka index.js folder itu. photos untuk server. cotoh untuk halaman. nx8v init membuat folder modules/, "dependencies": {}, dan repository yang menunjuk ke mega-repo internal NX8V.

Dependensi

repository di project.json adalah tempat modul diambil dan diterbitkan. Bawaannya repo internal NX8V. Saat materi dependensi dipublikasikan dari repo milik user, url diganti.

"repository": {
  "type": "git",
  "url": "https://github.com/nx8v/dependencies.git"
}

Satu versi sama dengan satu GitHub Release. Nama dan versi pada perintah menjadi tag <nama>-<versi>. Aset rilis disalin ke modules/<nama>/. Berkas masuknya index.js. Berkas lain di folder yang sama, misalnya app.js, ikut diunduh dan ikut diterbitkan.

Perintah dijalankan di folder proyek:

PerintahFungsi
nx8v i contoh@1.0.2pasang. Tag yang dicari: contoh-1.0.2
nx8v u contoh@1.0.2ganti versi modul yang sudah ada di dependencies. Angka versinya yang diganti
nx8v p contohnamalain@1.0.0terbitkan isi modules/contohnamalain/ ke repository
nx8v d contohhapus contoh dari dependencies, nx8v.lock, dan modules/contoh

Pasang menulis tiga tempat:

"dependencies": {
  "contoh": "1.0.2"
}
modules/contoh/index.js
{
  "dependencies": {
    "contoh": {
      "version": "1.0.2",
      "resolved": "https://github.com/nx8v/dependencies/releases/tag/contoh-1.0.2"
    }
  }
}

resolved di nx8v.lock adalah halaman rilis yang dipakai saat pemasangan. Nama yang tidak ada tag-nya tidak ditulis ke dependencies maupun modules. Bila tag tidak ketemu, perintah menampilkan daftar rilis yang ada.

Perbarui hanya untuk nama yang sudah terpasang. nx8v u contoh@1.0.2 mengganti berkas di modules/contoh/, versi di dependencies, dan catatan di nx8v.lock. Nama yang belum ada ditolak; pasang lebih dulu dengan nx8v i.

Terbitkan membaca modules/contohnamalain/. Folder itu wajib berisi index.js. Setiap berkas di folder itu dilampirkan sebagai aset rilis contohnamalain-1.0.0. Perintah ini memakai GitHub CLI dan akun yang sudah masuk:

gh auth login
nx8v p contohnamalain@1.0.0

Setelah terbit, dependencies dan nx8v.lock di proyek itu ikut mencatat versi tersebut. Rilis yang tag-nya sudah ada tidak ditimpa.

Hapus mengeluarkan nama dari daftar. nx8v d contoh menghapus kunci contoh di project.json dan nx8v.lock, lalu menghapus folder modules/contoh. Rilis di GitHub tidak dihapus.

4. HTTP server

const http = require('http');

const server = http.createServer((req, res) => {
  console.log(req.method, req.url);

  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ ok: true }));
});

server.listen(3000, () => console.log('http://localhost:3000'));

Request (req):

Properti/MethodKeterangan
req.methodGET, POST, …
req.urlpath + query, apa adanya
req.httpVersion"1.1"
req.headersobjek header (nama asli dari klien)
req.on('data', fn)body (bila ada)
req.on('end', fn)body selesai

Response (res):

MethodKeterangan
res.writeHead(status[, message][, headers])kirim status + header. Tanpa message, kalimat status mengikuti kode: 404 menjadi Not Found
res.setHeader(name, value)set satu header
res.getHeader(name)baca header
res.write(chunk)tulis body (di-buffer). chunk boleh string atau Buffer
res.end([chunk][, cb])kirim respons, tutup koneksi. Byte 0x00 di dalam PNG ikut terkirim
res.statusCodestatus default 200. Mengubah angka ini juga mengganti kalimat status

fs.readFile dan fs.readFileSync tanpa encoding mengembalikan Buffer, jadi gambar tidak rusak saat dikirim lewat res.end. Encoding 'utf8' tetap mengembalikan string. data.toString() memakai teks UTF-8.

Event server: listening, request, connection, close, error, websocket.

Catatan: server selalu membalas Connection: close (satu request per koneksi). Ini disengaja — pipelining belum didukung, dan lebih aman untuk browser.

5. Router ala Express

const app = require('router')();

app.use((req, res) => {
  console.log(req.method, req.url);       // middleware global
});

app.get('/user/:id', (req, res) => {
  res.json({ id: req.params.id });        // param dinamis
});

app.post('/api/login', (req, res) => {
  res.status(201).json({ ok: true, token: 'abc123' });
});

app.get('/lama', (req, res) => res.redirect('/baru'));

app.notFound((req, res) => {
  res.status(404).json({ error: 'tidak ada rute', path: req.url });
});

app.listen(5400, () => console.log('http://localhost:5400'));
APIKeterangan
app.get/post/put/delete/patch/all(path, handler)daftar rute
app.use([path,] fn)middleware (global atau ber-scope)
app.notFound(fn)handler 404 kustom
app.listen(port[, cb])jalankan server, mengembalikan http.Server
req.paramshasil parse param rute
res.status(code)set status (chainable)
res.json(obj)kirim JSON + header otomatis
`res.send(str\Buffer)`kirim teks/biner
res.redirect(url[, code])redirect (default 302)

Pola path yang didukung:

/user/:id          → req.params.id
/file/:name?       → opsional
/static/*          → req.params[0] berisi sisa path

Middleware bisa menghentikan rantai dengan return false.

6. Static file server

Versi produksi dari static handler (ETag, Range, HEAD, cache):

const http  = require('http');
const serve = require('static');

const handler = serve('public', { maxAge: 3600, index: 'index.html' });

http.createServer((req, res) => handler(req, res)).listen(3000);
// atau: app.use(handler)  (di router)
OpsiDefaultKeterangan
maxAge0detik untuk Cache-Control: public, max-age=N
indexindex.htmlfile untuk direktori
etagtruekirim ETag + dukung If-None-Match (304)
rangestruedukung Range (206 Partial Content)

Perilaku:

  • GET/HEAD saja; method lain → 405 + header Allow
  • If-None-Match / If-Modified-Since cocok → 304 (tanpa body)
  • Range: bytes=0-99 → 206 + Content-Range
  • Range tidak valid → 416
  • .. pada path (termasuk %2e%2e) → 403
  • File tidak ada → 404

7. WebSocket server

const http = require('http');
const server = http.createServer((req, res) => res.end('ws server'));

server.on('websocket', (ws) => {
  console.log('client tersambung');

  ws.send('selamat datang');

  ws.on('message', (msg) => {
    console.log('terima:', msg);
    ws.send('echo: ' + msg);
  });

  ws.on('close', () => console.log('client putus'));
});

server.listen(5300);

Upgrade ditangani otomatis: klien yang mengirim header Upgrade: websocket ke port yang sama akan diubah menjadi koneksi WebSocket (RFC 6455).

APIKeterangan
server.on('websocket', fn)koneksi WebSocket baru
`ws.send(text \Buffer)`kirim frame
ws.on('message', fn)pesan masuk (string)
ws.on('close', fn)koneksi ditutup
ws.close()tutup dari server

Ping/pong dijawab otomatis. Klien (browser) bisa memakai API WebSocket biasa:

const ws = new WebSocket('ws://localhost:5300/');
ws.onmessage = (e) => console.log(e.data);

8. HTTP/HTTPS client + fetch

http.get / http.request

const http = require('http');

http.get('http://127.0.0.1:3000/api/hello', (res) => {
  console.log('status:', res.statusCode, res.statusMessage);
  let body = '';
  res.on('data', (c) => { body += c; });
  res.on('end', () => console.log(body));
});
const https = require('https');           // sama, untuk https://

const req = https.request({
  hostname: 'jsonplaceholder.typicode.com',
  path: '/photos?_limit=5',
  method: 'GET',
  headers: { 'Accept': 'application/json' },
}, (res) => {
  let body = '';
  res.on('data', (c) => { body += c; });
  res.on('end', () => console.log(JSON.parse(body).length, 'item'));
});

fetch (global)

fetch('https://jsonplaceholder.typicode.com/photos?_limit=5')
  .then((r) => {
    if (!r.ok) throw new Error('HTTP ' + r.status);
    return r.json();
  })
  .then((photos) => console.log(photos.length, 'foto'))
  .catch((e) => console.error(e.message));
Objek responsKeterangan
res.oktrue bila status 200–299
res.statuskode status
res.statusTextteks status
res.headersobjek header (lowercase)
res.text()Promise<string>
res.json()Promise<object>

Catatan HTTPS: di Windows memakai WinHTTP (TLS 1.2/1.3, sertifikat dari cert store Windows, redirect dan de-chunk otomatis). Di Linux aktif bila dikompilasi dengan -DNX8V_USE_OPENSSL.

Chunked transfer (Transfer-Encoding: chunked) ditangani otomatis pada respons HTTP biasa.

nx8v dev

Memantau folder proyek, termasuk file di root seperti server.js. Dilewati: node_modules, .git, build, dist, .nx8v.

Simpan .html, .css, atau .svg memuat ulang halaman yang sedang terbuka. Server tetap jalan:

[watch] change detected: D:\proyek\public\index.html
[dev] browser reload

Simpan .js, .mjs, atau .json me-restart server, lalu halaman yang sama ikut memuat ulang setelah server hidup lagi:

[watch] change detected: D:\proyek\server.js
[dev] stopping server for restart...
[dev] restarting D:\proyek\server.js
[dev] server started (pid 1250)

Setelah nx8v diperbarui, refresh halaman sekali supaya skrip pemantau masuk. Simpan berikutnya memuat ulang sendiri. Bila server crash karena error sintaks, supervisor tetap hidup — perbaiki file dan server otomatis menyala lagi.

Komponen HTML (partial)

Tag apa pun bisa memuat file HTML lain. nx8v menggabungkannya saat halaman dikirim, tanpa JavaScript di browser:

<header partial="./header.html"></header>

./header.html dibaca dari folder yang sama dengan halaman (public/). Isi file masuk ke dalam tag, dan atribut partial dihapus. Simpan file komponen saat nx8v dev berjalan: halaman yang terbuka memuat ulang sendiri.

Path di luar folder public ditolak.

nx8v list

PID      PORT    PROJECT          DIR
1360     4000    Aplikasi demo    D:\NX8V\example
13204    5202    toko-demo        D:\NX8V\build\demotest

nx8v test

test('penjumlahan', () => {
  assert.equal(1 + 1, 2);
  assert.deepEqual([1, 2], [1, 2]);
  assert.throws(() => { throw new Error('x'); });
});

Output ✓/✗ per test + ringkasan; exit code 1 bila ada kegagalan. Assertion: equal, strictEqual, notEqual, deepEqual, deepStrictEqual, ok, truthy, notOk, throws, doesNotThrow.

Type=simple

1. Cara kerja

nx8v window
   │
   ├─▶ jalankan script (biasanya HTTP server) di event loop libuv
   │
   └─▶ buka jendela Win32 + WebView2
          └─▶ navigate ke http://127.0.0.1:<port>/
                 └─▶ halaman HTML/CSS/JS biasa
                        └─▶ window.nx8v  (bridge ke native)

Frontend tetap HTML/CSS/JS normal yang dilayani server lokal; backend adalah runtime NX8V sendiri. Tidak ada Electron, tidak ada Node, satu exe ~34 MB.

2. Menjalankan

nx8v window                                   # pakai project.json (main + port)
nx8v window server.js                         # script tertentu
nx8v window --url=http://localhost:3000       # URL eksplisit
nx8v window --title="Toko" --width=1200 --height=800

--title=nx8vjudul jendela

--height=desktop.height, atau 760tinggi jendela

--minimizedsama dengan --state=minimized

Tanpa argumen, NX8V membaca project.json (main dan nx8v.port).

server.listen selesai sebelum jendela membuka URL, jadi halaman index tampil saat unduhan data pertama masih berjalan.

Menyimpan .html, .css, atau .svg memuat ulang halaman di jendela. Menyimpan .js, .mjs, atau .json menutup jendela lalu membukanya lagi supaya kode server yang baru ikut jalan.

Menutup jendela lewat tombol X menghentikan proses dan mengembalikan prompt terminal (kecuali tray aktif — lihat §5). Ctrl+C di terminal menutup jendela yang sama.

Komponen HTML berlaku di dalam jendela, karena halamannya tetap dari server:

<header partial="./header.html"></header>

8. Packaging

nx8v package                       # dist/<nama>/
nx8v package --name=toko --out=release

Isi folder hasil:

dist/<nama>/
├── <nama>.exe          # aplikasi ada di dalam exe
├── WebView2Loader.dll  # otomatis bila proyek memakai bridge
├── start.cmd
└── README.txt
dist/<artifactName>     # pemasang Windows, misalnya Aplikasi-demo-Setup-1.0.0.exe
dist/<nama>-<versi>-linux-x64.tar.gz

Satu perintah nx8v package menulis dua berkas unduhan, seperti folder rilis: pemasang Windows Nama-Setup-versi.exe dan arsip Linux Nama-versi-linux-x64.tar.gz. Di Linux: tar -xzf arsip itu, masuk ke foldernya, lalu ./start.sh. Runtime Linux yang dibungkus adalah berkas nx8v-linux di folder yang sama dengan nx8v.exe. Jendela desktop Linux belum ada, jadi paket Linux menjalankan server.

server.js, project.json, dan public/ tidak ikut sebagai berkas terpisah. Saat exe dijalankan, nx8v membuka isi itu dari dalam exe ke cache pribadi. Pemasang dibuat oleh nx8v sendiri. Klik dua kali berkas setup: aplikasi dipasang di %LOCALAPPDATA%\<nama>, dengan pintasan desktop, Start Menu, dan entri hapus pemasangan. Skrip .nsi tetap ditulis. makensis hanya dipakai bila sudah terpasang.

Deteksi otomatis: bila ada file .js/.html yang memuat window.nx8v, nx8v.dialog, atau nx8v.setTitle, paket dianggap aplikasi desktop — WebView2Loader.dll disalin dan start.cmd menjalankan mode window.

Dilewati saat menyalin: node_modules, .git, build, dist, deps, out, .nx8v.

Bridge masukAddScriptToExecuteOnDocumentCreated + postMessage → WebMessageReceived
Bridge keluarPostWebMessageAsJson (host → halaman)
DialogIFileOpenDialog / IFileSaveDialog (shobjidl.h)

Kenapa dua jalur pump? uv_prepare hanya jalan saat loop berputar; libuv bisa memblokir lama menunggu I/O (IOCP). Timer 4 ms memastikan pesan Win32 tetap diproses → jendela tidak freeze.

Arah pesan: window.chrome.webview.postMessage() adalah halaman → host. Untuk host → halaman wajib PostWebMessageAsJson (memakai ExecuteScript + postMessage akan mengirim ke arah yang salah).

Tahap 1 — folder yang bisa diklik dua kali

  • Baca desktop.icon. Tanam ikon itu ke dalam exe hasil salinan, supaya Explorer menampilkannya.
  • Exe di samping project.json, bila dijalankan tanpa argumen, membuka nx8v window. start.cmd tidak wajib.
  • Gambar ikon di desktop.icon ikut disalin. PNG tidak perlu diubah menjadi ico oleh pengguna.

Tahap 2 — pemasang

  • nx8v package selalu menulis berkas sesuai artifactName, misalnya dist/Aplikasi-demo-Setup-1.0.0.exe.
  • Klik dua kali berkas itu. Jendela pemasangan terbuka dalam bahasa Inggris: folder, pintasan, dan tombol Install. Tidak ada jendela terminal.
  • Aplikasi dipasang di folder yang dipilih. Bawaan %LOCALAPPDATA%\<nama>.
  • Pemasang membuat pintasan Start Menu dan desktop dengan shortcutName bila kotak pintasan dicentang. Start Menu tidak berisi pintasan hapus.
  • Di folder pemasangan ada Uninstall.exe. Klik dua kali berkas itu untuk membuka jendela hapus. Pengaturan Windows > Aplikasi memakai berkas yang sama.
  • Folder tahap 1 tetap ada untuk dicoba tanpa memasang.
  • Skrip NSIS ikut ditulis. makensis hanya dijalankan bila ada di komputer.

Tahap 3 — menu yang mengikuti aplikasi

  • Item menu: label, id, enabled, checked, pemisah, dan submenu.
  • exit: false meniadakan Keluar bawaan. exitLabel mengganti tulisannya.
  • Klik kanan di halaman bisa diganti lewat nx8v.contextMenu.set([...]), bukan menu browser yang tetap.
